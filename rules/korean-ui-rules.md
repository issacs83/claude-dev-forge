# Korean UI Rules

한국어 인터페이스는 라틴 문자 기준으로 맞춘 서식을 그대로 쓰면 반드시 작아 보이고 답답해진다.
다음은 한국어 화면에만 적용되는 보정이다.

## 타이포그래피

| 항목 | 라틴 기준 | 한국어 보정 |
|---|---|---|
| 본문 크기 | 14px | **15–16px** |
| 캡션·보조 | 12px | **13px** |
| 행간 | 1.5 | **1.6–1.7** |
| 자간 | 0 | **-0.01em ~ -0.02em** |
| 한 줄 길이 | 45–75자 | **30–45자** |

- 한글은 같은 px 에서 라틴보다 작게 읽힌다. 12px 이하는 본문에 쓰지 않는다.
- 폰트: Pretendard → Noto Sans KR → system-ui 순으로 지정한다. 맑은 고딕 단독 지정은 피한다.
- 한글에 `font-weight: 300` 이하는 화면에서 흐려진다. 400 이상을 쓴다.
- 숫자와 영문이 섞인 줄은 숫자에 tabular figures 를 적용해 자릿수가 흔들리지 않게 한다.

## 줄바꿈

- `word-break: keep-all` 을 기본으로 한다. 단어 중간에서 끊기면 읽기가 급격히 나빠진다.
- 긴 제목은 `text-wrap: balance`, 본문은 `text-wrap: pretty`.
- 조사("을/를", "이/가") 만 다음 줄로 넘어가는 형태를 허용하지 않는다.

## 문장과 어조

- **결론을 먼저 쓴다.** "~하려면 먼저 ~을 해야 합니다" 보다 "~을 하세요. 그러면 ~됩니다".
- 한 문장에 한 가지만 담는다.
- 버튼은 **동사로 끝낸다**: "저장", "삭제", "내보내기". "확인"은 무엇을 확인하는지 불명확하므로 피한다.
- 높임은 "-합니다" 로 통일한다. "-해요" 와 "-하십시오" 를 한 화면에 섞지 않는다.
- 사실과 판단을 분리한다. "전압이 낮습니다(사실) / 충전이 필요합니다(판단)".

## 용어

- 화면 전체에서 한 개념에 한 단어만 쓴다. "설정/환경설정/세팅" 을 섞지 않는다.
- 불필요한 외래어를 한글로 대체하지 않는다. 현장에서 쓰는 말을 쓴다(예: "펌웨어" 를 "굳은모듬" 으로 바꾸지 않는다).
- 단위는 항상 표기한다. 숫자와 단위 사이는 얇은 간격(`&thinsp;` 또는 0.15em)을 둔다.
- 영문 약어는 첫 등장 시 한 번 풀어 쓴다: "SOC(잔량)".

## 레이아웃

- 한국어 레이블은 영어보다 짧다 → 레이블 열 폭을 그대로 두면 빈 공간이 생긴다. 실제 문자열로 측정한다.
- 반대로 설명문은 영어보다 길어지는 경우가 많다 → 2줄 기준으로 높이를 잡는다.
- 텍스트가 잘릴 때는 말줄임(`…`) + `title` 속성. 넘침을 방치하지 않는다.
- 다국어를 지원한다면 한국어·영어 양쪽에서 레이아웃을 확인한다. 한쪽만 맞춰진 화면은 미완이다.

## 입력

- IME 조합 중 이벤트를 주의한다. `compositionstart`/`compositionend` 를 고려하지 않은
  실시간 검색은 자모 단위로 질의를 날린다.
- 한글 초성 검색을 지원하면 사용성이 크게 올라간다(선택).
- 이름·주소 필드에 라틴 전용 정규식 검증을 걸지 않는다.

## 날짜·숫자

- 날짜: `2026-09-22` (ISO 8601) 또는 `2026년 9월 22일`. `09/22/2026` 은 쓰지 않는다.
- 요일 표기는 "(월)" 형식.
- 천 단위 구분자 사용. 단, 연도·식별번호에는 쓰지 않는다.
- 통화는 `12,340원` 또는 `₩12,340`. 화면 내에서 하나로 통일한다.

## 금지

- 이모지를 인터페이스 아이콘으로 사용
- 본문 12px 이하
- `word-break: break-all` 을 한국어 본문에 적용
- "확인 / 취소" 만으로 된 파괴적 동작 확인 창 — 무엇이 일어나는지 동사로 쓴다
- 기계 번역투: "당신의 설정이 저장되었습니다" → "설정을 저장했습니다"
- AI 티 나는 문구: "~을 도와드리겠습니다", "훌륭합니다!", 느낌표 남용
